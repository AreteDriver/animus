## ADL-20260705-001

**Project:** Animus
**Decision Class:** ARCH

**Decision:**
Fix three critical gaps in the Architect Citizen (001) that rendered it noisy and fragile: (1) EvalStore API contract mismatch causing eval queries to crash, (2) monorepo-wide scope producing 211 irrelevant observations per scan, (3) proposal generator ignoring focus-path context and surfacing proposals for unrelated packages.

**Chosen Option:**
- Fix `eval_evidence.py` to use the new `EvalStore(backend: DatabaseBackend)` constructor via `create_backend()` helper
- Add `focus_paths` parameter to `ArchitectCitizen` and wire it into `BootstrapLoop` with `"packages/core/animus"`
- Update `generate_proposal()` to sort observations by focus-path relevance before picking the highest-severity item, and populate `affected_components` from actual observed files

**Rejected Options:**
- Keep monorepo-wide scanning and filter post-hoc: would still waste tokens on 30+ projects
- Add a `max_observations` cap without focus: symptom fix, not root cause
- Move focus logic into BootstrapLoop only: would leave CLI/MCP tools unfocused

**Why:**
- The Architect produced 211 observations, 190+ of which were from Forge, Head, Lugh, and other packages outside the Mind Foundation scope. The generated proposal targeted `on_speech` (1,214 lines in Head/voice), which is completely irrelevant to the current Phase 0 citizen work.
- `EvalStore.__init__()` changed from `EvalStore(db_path: str)` to `EvalStore(backend: DatabaseBackend)` in a recent Forge update. The eval query path in `eval_evidence.py` was silently catching the `TypeError` and returning `[]`, masking the regression.
- Without focus-path awareness, `generate_proposal()` used hardcoded `affected_components=["Factory", "Kernel"]`, making it impossible for the Citizen Council to deduplicate or prioritize proposals correctly.

**Tradeoffs Accepted:**
- `focus_paths` uses glob strings (e.g., `"packages/core/animus/citizens/*.py"`) which are Forge-analyzer-specific; if we switch analyzers, the format may need translation
- Focus-path filtering happens at observation time, so any non-matching observations are discarded rather than stored for later review
- `create_backend()` assumes SQLite; PostgreSQL eval backends would need a URL parameter

**Revisit If:**
- The Forge analyzer gains native scope-limiting that makes our `focus_paths` wrapper redundant
- We need cross-package proposals (e.g., a change that spans Core + Forge APIs)
- The eval backend changes again and `create_backend()` becomes unsupported

**Addendum 2026-07-05**: All 187 citizen/bootstrap tests pass after fixes. Architect now produces 21 focused observations (down from 211) and targets `observe_outdated_claims` in `knowledge_curator.py` — a component we are actively building.

## ADL-20260705-002

**Project:** Animus
**Decision Class:** UX

**Decision:**
Fix five citizen quality issues discovered during end-to-end citizen run analysis:
1. ConversationDesigner false-positive when no conversation logs exist
2. KnowledgeCurator false-positive when no `topics/` or `docs/` directories exist
3. TestOracle unprioritized broad output (20+ uncitizened modules without scoring)
4. CitizenCouncil ranking formula rewarding vague proposals over file-level specifics
5. Eval evidence module emitting repeated "no such table" warnings every cycle

**Chosen Option:**
- Change `ConversationDesigner.observe_repeated_prompts()` and `KnowledgeCurator.observe_orphan_topics()` to return `[]` instead of a "medium/low" observation when their data source is absent — this is expected state, not an actionable finding
- Score uncitizened modules by line count in `TestOracle.observe_uncitizened_modules()`, surface only top 5, severity scales with size (`>200` lines = `high`), and skip `.venv/`/`node_modules/` noise
- Add `specificity_bonus` to `CitizenCouncil._compute_priority_score()`: `+0.15` per file-level component path (containing `.` or `/` depth > 1), capped at `0.5`
- Cache `_eval_db_available` at module level in `eval_evidence.py`; set to `False` on first "no such table" or import failure, suppressing repeated warnings for the session

**Rejected Options:**
- Keep observations but downgrade severity to `"info"`: would still pollute the proposal pipeline and council ranking
- Filter post-hoc in BootstrapLoop: would leave the citizens themselves producing noisy output for CLI/MCP direct use
- Use a class-level eval cache instead of module-level: would not survive across citizen instances in the same session

**Why:**
- These five issues were the only actionable defects in a full Phase 0 citizen run. After fixes, all citizens produce zero false positives in the "no data" case, the Council correctly ranks file-specific proposals above vague ones, and eval query overhead drops from 4× WARN logs per cycle to silent degradation.
- The `specificity_bonus` directly addresses the ranking inversion where a vague ConversationDesigner proposal (`affected_components=["all_citizens"]`) outranked a specific Architect proposal (`affected_components=["packages/core/animus/citizens/knowledge_curator.py"]`).
- 2809/2809 tests pass (2 pre-existing config test failures unrelated to citizens).

**Tradeoffs Accepted:**
- Module-level `_eval_db_available` persists for the Python process lifetime; if eval DB is created mid-session, the cache will remain `False` until process restart. Acceptable because eval DB is infrastructure, not runtime state
- Top-5 limit on uncitizened modules may hide medium-sized uncovered files if many large ones exist; the line-count sort ensures the most impactful gaps surface first

**Revisit If:**
- Conversation logging becomes mandatory (then "no logs" should become a finding again)
- We adopt a documentation-driven repo structure where missing `topics/` is an error condition
- Council ranking needs additional dimensions (e.g., business impact tags)

## ADL-20260705-003

**Project:** Animus
**Decision Class:** ARCH

**Decision:**
Complete three remaining citizen pipeline tasks to achieve full end-to-end functionality:
1. Add heuristic fallback to Architect when Forge analyzer returns empty suggestions
2. Fix focus path expansion — convert directory paths like `"animus"` to `"animus/**/*.py"` for Forge
3. Run live BootstrapLoop cycle verifying citizen → queue → commission pipeline

**Chosen Option:**
- Implement `_observe_heuristics()` in Architect with five checks: file size + missing docstring, cyclomatic complexity >10 via AST, TODO/FIXME/HACK comment detection, missing `__init__.py` in package dirs, and unused import detection
- Add `_expand_focus_paths()` that converts bare directory paths to `**/*.py` globs before passing to Forge; update BootstrapLoop from `"packages/core/animus"` to `"animus"` to match actual repo structure
- Fix remaining Architect false positives in `observe_conversations()` and `observe_evaluations()` to return empty when no data source is present (same pattern as ADL-20260705-002)

**Rejected Options:**
- Use only Forge and accept zero observations when it returns empty: would leave the Architect blind during initial setup or when Forge is down
- Use `os.walk()` instead of `Path.rglob()`: less idiomatic, more verbose
- Keep BootstrapLoop passing `"packages/core/animus"`: that path doesn't exist in this repo layout

**Why:**
- The Forge analyzer requires file glob patterns, not directory names. Passing `"animus"` caused `IsADirectoryError`; passing `"animus/**/*.py"` produces 186 actionable observations (long functions, missing docstrings, etc.)
- Heuristic fallback ensures the Architect is never blind: when Forge is unavailable, AST-based analysis still surfaces high-complexity functions and tech-debt comments
- Live BootstrapLoop cycle verified the complete pipeline: 3 proposals generated (Architect, KnowledgeCurator, TestOracle), submitted to ProposalQueue, ranked by CitizenCouncil with specificity bonus working correctly
- 2761/2761 tests pass

**Tradeoffs Accepted:**
- Heuristic complexity analysis uses a simplified AST walk (If/For/While/Except/With/Assert/BoolOp nodes only); does not count `match` statements or ternary expressions. Sufficient for directional guidance, not precise cyclomatic complexity metrics
- Unused import detection is naive (only checks top-level names, not attribute chains like `module.sub.func`). Catches obvious cases, misses re-exports
- Focus path expansion adds `**/*.py` to all bare directories; if Forge ever needs non-Python files (`.yaml`, `.md`), this will need extension

**Revisit If:**
- We need more precise complexity metrics (e.g., McCabe integration)
- Forge analyzer gains native directory-path support, making `_expand_focus_paths()` redundant
- We need heuristic analysis for non-Python files (e.g., TypeScript, Rust in future packages)

**Project:** Animus
**Decision Class:** ARCH

**Decision:**
Close Kill Criterion #5 (Continuity Guarantee across ≥5 sessions) by adding targeted tests to the kernel head core suite and verifying full test-suite health.

**Evidence:**
1. `TestHeadCheckpointStore.test_five_session_continuity` — simulates 5 sequential sessions through SQLite checkpoint persistence. Each session loads prior state, appends 2 new messages, saves updated checkpoint. Final verification: 10 messages survive, turns=5, summary intact.
2. `TestSessionBootstrap.test_previous_session_loaded_when_recent` — verifies SessionBootstrap loads checkpoints within 24h window and surfaces messages, summary, and turn count on new session startup.
3. Full test-suite verification:
   - Kernel head core: **83/83 passed**
   - Full kernel suite: **190/190 passed**
   - Core citizens: **71/71 passed**
   - Full core suite: **2,899/2,899 passed, 8 skipped**

**Mechanisms Already in Place:**
- `HeadCheckpointStore` → SQLite-backed persistence at `~/.animus/sessions/head.db`
- `SessionBootstrap` → loads active tasks, recent memories, recent decisions, previous session (24h window)
- `HeadContextManager` → summary survives `clear()`, pruning preserves tool-call pairs, keeps ≥2 user turns
- `LocalMemoryStore` → semantic memory persists across process restarts

**Why:**

**Tradeoffs Accepted:**
- The 24h window in SessionBootstrap is hardcoded; sessions older than 24h are ignored to prevent stale context from overwhelming the current session
- Full message history is not infinitely retained; `HeadContextManager` prunes when approaching token budget, preserving only summary + recent turns
- Checkpoint store uses SQLite; large deployments may need PostgreSQL backend for concurrent access

**Revisit If:**
- We need configurable continuity window (e.g., 48h, 7d) per project
- Session state grows beyond SQLite single-writer limits
- We need real-time sync across multiple devices (currently single-device only)

**Project:** Animus

**Decision:**
Explicitly tier the Citizen constitutional layer (P01–P07 Mind Charter) by creating a Citizen Integration Contract that maps rights, responsibilities, and governance mechanisms to concrete code components. This bridges the gap where citizenhood was real in philosophy documents but invisible in the Canonical Architecture and roadmap.

**Chosen Option:**
- Create `docs/architecture/CITIZEN_INTEGRATION_CONTRACT.md` as the bridge document between Mind Charter and Canonical Architecture
- Keep the Mind Charter at the philosophy tier (P01–P07 corpus files in `~/.animus/corpus/`)
- Map each right/responsibility to existing code with honest gap status: **OPERATIONAL**, **PARTIAL**, or **NOT YET IMPLEMENTED**
- Document the informal "3-of-5 citizen quorum" as **NOT YET IMPLEMENTED**; the actual safety check is the human `ApprovalGate`
- Propose (but do not implement) `CitizenIdentity` and `GovernanceAction` schema extensions for future phases

**Rejected Options:**
- **Operationalize everything immediately**: would require `DurableObjectStore` schema changes, PDP principal-class extensions, and quorum mechanics before the architecture is stable. Too much churn for a documentation-reconciliation phase.
- **Declare it purely aspirational**: would invalidate the existing `CitizenCouncil` and `ForgeCommissioner` operating in production. The code already does real citizen governance work; pretending it's just philosophy is dishonest.
- **Fold citizenhood into the generic `{user_id, agent_id, role}` context envelope**: would collapse the richer constitutional concept (continuity-bearing, governance-participating, rights-holding) into flat RBAC. This is what the v2 Reconciled doc already does, and it's the root cause of the gap.

- The search for "Citizen" in `roadmap-to-10.md` and the Canonical Architecture docs returns zero hits. The 5-citizen council and Architect Citizen operate in practice but are not documented as load-bearing architecture.

**Tradeoffs Accepted:**
- The contract introduces maintenance burden: every code change affecting identity, continuity, or governance must update the mapping table. This is intentional friction — if the architecture drifts from the constitution, the contract surfaces it.
- Schema extensions (`CitizenIdentity`, `GovernanceAction`) are proposed but not implemented; they may drift from actual implementation if built later. The contract explicitly labels them "NOT YET IMPLEMENTED" to prevent false claims.
- Seven gaps (G1–G7) are now publicly visible. This is honest but may appear as admissions of incompleteness to external readers. The alternative (hidden gaps) is worse.

**Revisit If:**
- We implement G1–G7 gaps and the contract becomes a redundant layer that duplicates docstrings
- We decide citizenhood is purely metaphorical and remove architectural weight from it
- The v3 architecture makes citizenhood a first-class runtime primitive (e.g., `CitizenIdentity` table, `CitizenCouncil.quorum_vote()`), at which point this contract is superseded by the schema registry itself

## ADL-20260722-001

**Project:** Animus
**Decision Class:** FEAT

**Decision:**
Add live model swap, checkpoint model persistence, and model pin commands to the Head REPL. Users can now switch between installed Ollama models mid-session, have their last-used model restored on restart, and pin model digests for tamper detection.

**Chosen Option:**
- `/model <name>` — swap to an installed model (exact match or unique prefix); preserves conversation context
- `/model <name> --warm` — swap and trigger a warmup completion to preload into VRAM
- `/model recommend` — cross-reference hardware detection with installed models and suggest best fits
- `/model stats` — per-model telemetry (latency, tokens/sec, fallback count) aggregated across the session
- `/model pin <name>` / `/model unpin <name>` / `/model pins` — expose `ModelPinStore` digest verification via REPL
- Checkpoint schema extended with `model TEXT` column; bootstrap restores previous model if still installed
- Context-budget guard: auto-prunes history when swapping to a smaller context window

**Rejected Options:**
- Require restart to change models: would lose session context and break the continuity promise (KC #5)
- Pin storage in SQLite instead of JSON: `ModelPinStore` already uses JSON; SQLite migration not justified for 1–2 KB of data
- Show *all* Ollama models (not just installed) in recommendations: would suggest models the user hasn't pulled, creating confusion

**Why:**
- Local model users frequently want to switch between a fast model (e.g., qwen2.5:14b for quick tasks) and a powerful one (qwen2.5:32b for deep reasoning) without losing conversation context
- The 24h continuity window (KC #5) was model-agnostic — restoring context but forgetting which model was active created a jarring experience
- Model pins (E12 security feature) existed in `ModelPinStore` but had no user-facing interface; exposing them in the REPL makes tamper detection actionable

**Tradeoffs Accepted:**
- Prefix matching on model names can be ambiguous (e.g., `qwen2.5` matches both `:14b` and `:32b`); ambiguous cases are rejected with a warning rather than silently picking one
- Checkpoint store now has a `model` column; existing checkpoints without the column will default to empty string on load, which gracefully falls back to the CLI default
- `/model stats` telemetry is in-memory only (per-session); no cross-session aggregation yet

**Revisit If:**
- We add cloud providers to Head REPL (currently local-only); `/model` semantics would need to change
- Ollama API changes how digests are exposed, breaking `fetch_ollama_digest()`
- Users request cross-session telemetry persistence or model usage analytics dashboard

## ADL-20260722-002

**Project:** Animus
**Decision Class:** ARCH

**Decision:**
Extract and internalize the browser-automation concept from `turbowebfetch` (MIT-licensed, 97-star solo repo) into first-class Animus infrastructure.  Create `packages/core/animus/browser/` — a nodriver-based bridge with anti-detection emulation, Readability→clean-text extraction fallback, DurableObjectStore caching, PolicyDecisionPoint-aware rate limiting, and MCP-native `fetch` / `fetch_batch` tools.

**Chosen Option:**
- Port the core idea (isolated Chrome per request, human-emulation patterns, extraction pipeline) into Animus-native Python under `packages/core/animus/browser/`
- Discard the TypeScript MCP wrapper; reimplement tool schemas in Animus's existing Python MCP stack
- Add deterministic, seedable emulation (`scroll.py`, `timing.py`, `mouse.py`) for reproducible tests
- Integrate `DurableObjectStore` for rendered-page caching instead of the upstream's no-cache design
- Integrate existing `RateLimitedDomain` / `PolicyDecisionPoint` for domain throttling instead of hardcoded 60/min
- Keep `nodriver` as optional dependency with graceful degradation (imports succeed, instantiation raises `RuntimeError` with install hint)

**Rejected Options:**
- Depend on `turbowebfetch` as an upstream package: browser automation is an arms race (Chrome updates, Cloudflare patches); waiting on a solo maintainer's issue tracker would block Research Guild harvester runs
- Extend the existing Playwright-based `packages/forge/src/animus_forge/browser/automation.py`: Playwright is heavier and lacks the anti-detection escalation patterns (headed retry, human scroll/timing) that make turbowebfetch effective
- Create a new top-level `packages/infra/` package: would fracture the monorepo structure; `packages/core/animus/browser/` keeps browser logic adjacent to `discovery`, `network`, and `ogma`

**Why:**
- The Research Guild's harvester currently relies on raw HTTP fetching.  JS-heavy sites (documentation portals, SPAs, modern SaaS landing pages) return empty or malformed content.  A real-browser backend is necessary for reliable ingestion.
- `turbowebfetch` is small (~1,500 LOC) and well-structured, but its maintainer has 9 repos and infrequent updates.  Browser automation breaks unpredictably when target sites upgrade bot detection.  Ownership aligns with Animus's "sovereign AI operating environment" principle (ADL-20260705-001).
- The extraction pipeline (Readability → clean-text fallback) and human-emulation modules are directly reusable and improve on the existing Playwright automation's lack of anti-detection sophistication.

**Tradeoffs Accepted:**
- `nodriver` is a younger project than Playwright/Selenium; API stability risk is offset by its lightweight CDP-only design and our ability to pin + patch
- Each fetch spawns a fresh Chrome (~200–400 MB), so 14 concurrent requests need ~4 GB RAM; acceptable for daemon-backed async queuing but not for synchronous burst
- No headless HTTP status code from nodriver; we infer 200 from successful navigation and fall back to `window.performance` where available
- Readability dependency (`readability-lxml`) is optional; without it the fallback raw-text extractor is slightly noisier

**Revisit If:**
- `nodriver` is abandoned or its Chrome compatibility breaks for >30 days and migration to Playwright/CDP directly is cheaper
- Research Guild switches to a third-party scraping service (e.g., ScrapingBee, Bright Data) that makes local browser automation redundant
- Memory per-fetch becomes a bottleneck on the target deployment host and we need persistent browser pools instead of per-request isolation
