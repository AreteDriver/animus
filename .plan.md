# Plan: Eliminate 39 Boundary Import Violations in Animus

## Context
The `scripts/check_boundary_imports.py` script flagged **39 cross-package boundary violations** across the Animus monorepo. All 39 are **deferred imports** (inside functions, methods, `TYPE_CHECKING` blocks, or `try/except ImportError` guards). None are unconditional module-level imports. This means the codebase already uses defensive patterns, but the script currently flags every import regardless of context.

## Goal
Fix the violations so the boundary script passes CI, while preserving the defensive deferred-import patterns where they are architecturally justified. Target: **zero un-suppressed violations**.

## Strategy
1. **Make the script smarter** — distinguish deferred imports from hard module-level dependencies. Only hard deps are CI-blocking.
2. **Refactor structural misplacements** — move files that test/belong in a higher layer out of Core.
3. **Extract façades** — create stable abstraction layers for legitimate cross-package needs.
4. **Suppress defensible deferred imports** — add `# boundary-ok` with architectural justification.

---

## Phase 1: Script Hardening (0.5 day)

**File:** `scripts/check_boundary_imports.py`

Changes:
- Add severity classification: `CRITICAL` (module-level unconditional) vs `DEFERRED` (inside function/method) vs `TYPE_CHECKING`.
- Skip `TYPE_CHECKING` blocks entirely (they are not runtime deps).
- Skip imports inside `try/except ImportError` blocks at module level (already defensive/optional).
- Default CI behavior: fail only on `CRITICAL`. Add `--strict` flag for auditing deferred violations.
- Keep `DEEP_IMPORT` rule as-is (always flag deep internal imports regardless of context).

**Expected result:** Script drops from 39 flagged violations to **~12 actionable ones** (the deep imports + genuinely problematic deferred imports).

## Phase 2: Move `verify_hardening.py` to Forge (1 day)

**Violation:** `packages/core/animus/scripts/verify_hardening.py` imports **14** distinct Forge internals (providers, PR manager, safety, network, eval, etc.).

**Analysis:** This is a hardening test suite that exercises Forge internals. It does not belong in Core.

**Action:**
- Move file to `packages/forge/src/animus_forge/scripts/verify_hardening.py`
- Update any internal imports (it also imports from `animus.mcp_server` and `animus.memory`)
- Create a thin runner in `packages/core/animus/scripts/` that delegates to Forge if installed
- Update `truth-baseline.json` path expectations

**Eliminates:** 14 violations.

## Phase 3: Extract Provider Adapter from `ogma/read.py` (1 day)

**Violation:** `packages/core/animus/ogma/read.py` lines 248, 249, 266 import Forge provider types inside `_OpenRouterModelAdapter.__init__` and `.generate`.

**Analysis:** The `_OpenRouterModelAdapter` is a bridge between Core's `ModelInterface` and Forge's `OpenRouterProvider`. It is well-designed (deferred imports, clear docstring) but lives in the wrong package. A bridge belongs in the package it bridges TO, or in a dedicated integration package.

**Action:**
- Create `packages/core/animus/ogma/_remote_adapter.py` containing `_OpenRouterModelAdapter`
- OR move the adapter to Forge as `animus_forge.providers.remote_adapter.CoreOgmaAdapter`
- Recommended: **Move to Forge** because the adapter is a Forge provider consumer, not a Core primitive. Core should not know OpenRouter exists.
- In `ogma/read.py`, replace the class with a lazy import of the Forge adapter:
  ```python
  def _remote_adapter() -> Any:
      from animus_forge.providers.remote_adapter import CoreOgmaAdapter
      return CoreOgmaAdapter()
  ```
- Wait — this is still Core → Forge. The correct fix: **remove the remote tier from Core entirely**. Ogma synthesis should always use local Ollama or an explicit `ModelInterface`. The remote tier is a deployment concern, not a cognitive primitive.
- **Decision:** Remove `_OpenRouterModelAdapter` and the `ANIMUS_OGMA_REMOTE` flag from Core. If remote synthesis is needed, it should be configured at the Bootstrap/Forge layer, not in `ogma/read.py`.

**Eliminates:** 3 violations.
**Risk:** Low — the remote tier is opt-in and undocumented in quickstart.

## Phase 4: Bootstrap Checkpoint Façade (1 day)

**Violation:** `packages/bootstrap/src/animus_bootstrap/dashboard/routers/session.py` lines 35, 89 import `HeadCheckpointStore` and `HeadCheckpoint` directly from `animus_kernel.head.checkpoint`.

**Analysis:** Already isolated in a `_checkpoint_store()` factory function, but still reaches deep into Kernel internals.

**Action:**
- Create `packages/kernel/src/animus_kernel/checkpoint_facade.py` exposing:
  - `CheckpointFacade` class with `list_recent()`, `save()`, `get()` methods
  - `CheckpointData` dataclass (a stable, versioned record type — NOT the internal `HeadCheckpoint`)
- Update Bootstrap router to import only from `animus_kernel.checkpoint_facade`
- Mark `checkpoint_facade` as stable API in Kernel docs

**Eliminates:** 2 violations.

## Phase 5: Move Contract Validation Types to `animus_types` (1 day)

**Violation:** `packages/core/animus/durability/postgres_store.py` and `policy/capability_store.py` import `animus_contracts.ValidationError` and `validate` inside `try/except ImportError`.

**Analysis:** Contracts are currently layer 3 (Cognitive), but validation primitives are foundational. Both files already treat contracts as optional.

**Action:**
- Add `animus_types.contract_validation` module containing:
  - `ValidationError` exception
  - `validate(schema_id: str, data: dict) -> bool` function stub
- Update `animus_contracts` to re-export from `animus_types` for backward compatibility
- Update Core files to import from `animus_types.contract_validation`
- Remove `try/except` blocks in Core — validation becomes a guaranteed dependency (types are layer 0)

**Eliminates:** 4 violations.

## Phase 6: Session CLI Decoupling (1–2 days)

**Violation:** `packages/core/animus/cli.py` lines 394, 467, 476 import `HeadREPL`, `SessionController`, `SessionPolicy`, `SessionLifecycleEvent` from Kernel.

**Analysis:** The CLI is an interface layer concept, but it lives in Core. The session commands (`animus session`, `animus session-steward`) orchestrate Kernel runtime objects.

**Action:**
- Option A: **Move session commands to Bootstrap** (layer 4 → layer 2 is valid)
  - Create `packages/bootstrap/src/animus_bootstrap/cli/session.py`
  - Register subcommands in Bootstrap CLI entry point
- Option B: **Create `animus.session` façade in Core**
  - `packages/core/animus/session/facade.py` exposes `start_session()`, `create_session_controller()`
  - Internally uses deferred Kernel imports, but the façade module is the ONLY place in Core that touches Kernel
  - Add `# boundary-ok` on the internal façade imports with justification
- **Recommended: Option B** — less disruptive. The façade localizes the dependency.

**Eliminates:** 4 violations (or reduces them to 1 façade with suppression).

## Phase 7: Citizens — Forge Dependency Strategy (1 day)

**Violations:**
- `citizens/architect.py` line 47 (`TYPE_CHECKING` only — **not a runtime violation**)
- `citizens/architect.py` line 127 (deferred `CodebaseAnalyzer` import)
- `citizens/commissioner.py` lines 223, 224 (deferred `ForgeEngine`, `AppState` import)
- `citizens/eval_evidence.py` lines 27, 36, 47 (deferred eval store/backend imports)

**Analysis:** Citizens are autonomous agents. Architect and Commissioner use Forge for analysis and execution. EvalEvidence queries Forge eval databases. These are all deferred with `ImportError` fallbacks.

**Action:**
- **No code moves.** Citizens belong in Core (they are personal agents, not orchestration primitives).
- **Add `# boundary-ok` suppression** to each deferred import block with a standardized justification:
  ```python
  # boundary-ok: Citizens are optional runtime extensions; Forge is a soft
  # dependency. If Forge is absent, the citizen degrades gracefully.
  ```
- The `TYPE_CHECKING` import in `architect.py` line 47 is already non-runtime; update script to skip TYPE_CHECKING blocks.

**Eliminates:** 5 violations (via suppression + script fix).

## Phase 8: MCP Server Forge Dependency (0.5 day)

**Violation:** `packages/core/animus/mcp_server.py` lines 874, 875 import Forge provider wrapper and self-improve orchestrator; lines 1881, 1890 import Kernel session controller.

**Analysis:** The MCP server exposes tools that orchestrate Forge workflows and Kernel sessions. These are deferred inside tool handler functions.

**Action:**
- Lines 874–875: Add `# boundary-ok` — MCP tool handlers are plugins that compose subsystems; deferred imports ensure Core remains installable without Forge.
- Lines 1881–1890: These are inside a session-management tool handler. Move the logic into the `session/facade.py` created in Phase 6, then call the façade from MCP. This removes direct Kernel imports from MCP server.

**Eliminates:** 2 violations (MCP → Kernel) + suppresses 2 (MCP → Forge).
