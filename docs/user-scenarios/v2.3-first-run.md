# User Scenario: v2.3 First-Run — Architect Citizen Walkthrough

**Last verified:** 2026-07-16
**Animus version:** 2.3.0
**Platform:** Linux (Ubuntu 22.04+ recommended)
**Time target:** ≤ 5 minutes from clone to first proposal

---

## Goal
Install Animus from the public repository and generate your first improvement proposal using the Architect Citizen — without writing code.

## Prerequisites

- Python 3.11+ (`python3 --version`)
- pip (`python3 -m pip --version`)
- ~500 MB free disk space
- No existing `.animus/` directory in your home folder (or willingness to use a fresh one)

---

## Step-by-Step

### 1. Clone the repository

```bash
git clone https://github.com/your-org/animus.git
cd animus
```

### 2. Install core packages

```bash
pip install -e packages/types/ \
  -e "packages/core/[dev]" \
  -e packages/kernel/ \
  -e packages/contracts/
```

> **Note:** The `[dev]` extra for core includes pytest and development dependencies. For a minimal install, use `-e packages/core/` instead.

### 3. Verify the installation

```bash
python3 -c "import animus; print('Animus installed:', animus.__version__)"
```

Expected output:
```
Animus installed: 2.3.0
```

### 4. Run the Architect Citizen

The Architect Citizen scans your codebase for technical debt and generates an improvement proposal. By default it scans the current working directory. To scope it to the Animus repository:

```bash
export ANIMUS_CITIZENS_CODEBASE_PATH="$(pwd)"
python3 -m animus.cli architect --focus codebase
```

Expected output (truncated):
```
# Running Architect Citizen scan...

## Codebase Observations (N found)
- [MEDIUM] Long function: on_speech — Function has 1325 lines...
- [LOW] Missing module docstring: scripts/docs-validate.py
...

## Proposal Generated: Architect Proposal: Technical debt: ...
**ID:** ADL-20260716-XXXXXX
**Problem:** ...
**Confidence:** high (78%)
**Recommendation:** Refactor structural architecture to reduce coupling...
**Effort:** 2.0h
**Components:** Factory, Kernel
```

### 5. (Optional) Store the proposal in memory

Add `--store` to persist the proposal in Animus's SQLite memory:

```bash
python3 -m animus.cli architect --focus codebase --store
```

## What Just Happened

1. **Install** — You installed four Animus packages in editable mode.
2. **Verify** — You confirmed the core package imports correctly.
3. **Scan** — The Architect Citizen performed static analysis on the Python files in the repository.
4. **Proposal** — It identified patterns (long functions, missing docstrings, TODOs) and generated a structured improvement proposal with estimated effort and risk assessment.

No API keys were required. The Architect Citizen works entirely via local static analysis.

## Troubleshooting

### "Citizens are disabled in configuration"
Citizens are enabled by default (`citizens.enabled = True`). If you see this message, you may have an old config file at `~/.animus/config.yaml` with `citizens.enabled: false`. Delete or update that file.

### Scan takes too long / scans the wrong directory
Without `ANIMUS_CITIZENS_CODEBASE_PATH`, the Architect falls back to the parent of the data directory, which may be your home folder. Always set this variable to scope the scan.

### Import errors during install
Ensure you install `packages/types/` first (or in the same `pip install` command). It is a sibling dependency of core.

### Proposal says "No actionable findings"
This happens on very small or well-structured codebases. Try `--focus all` to include conversation and evaluation observations (requires log directories to be configured).

## Next Steps

- **Review the proposal:** Proposals include an `ADL-` ID. You can track them via `animus proposal-queue list`.
- **Approve a proposal:** `animus proposal-queue approve <id>`
- **Commission via Forge:** For approved proposals, the Forge Commissioner can transform them into executable workflows.
- **Explore other citizens:**
  - `animus conversation-designer` — Detects correction loops and vague prompts in your transcripts
  - `animus knowledge-curator` — Finds stale references and contradictions in documentation
  - `animus test-oracle` — Identifies gaps in test coverage
