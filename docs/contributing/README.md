# Contributing to Animus

> This project exists because current AI assistants don't serve users — they serve platforms. If you share that frustration, you're in the right place.

---

## Quickstart for Contributors

1. [Set up your dev environment](setup.md) — Python, Git, local LLM
2. Read the [guidelines](guidelines.md) — code style, PR process
3. Understand the [workflow](workflow.md) — Git flow, CI gates, release process
4. Check the [debugging guide](debugging.md) — when things go wrong

---

## Philosophy

- **Working code over perfect architecture**
- **User sovereignty over convenience features**
- **Privacy by default over opt-in protection**
- **Transparency over polish**

---

## What to Contribute

| Area | Good first issues | Skills needed |
|---|---|---|
| Documentation | Fix stale links, clarify instructions | Markdown, empathy |
| Tests | Increase coverage in `packages/core/` | Python, pytest |
| Forge workflows | Add new YAML skill definitions | YAML, domain knowledge |
| Bootstrap UI | Dashboard improvements | FastAPI, HTMX |
| Schemas | Validate or extend JSON schemas in `packages/contracts/` | JSON Schema |

---

## Code of Conduct

Be direct. Be kind. Assume good intent. Disagree with the idea, not the person.

---

## Getting Help

- Open a [GitHub Discussion](https://github.com/your-org/animus/discussions) for questions
- Open a [GitHub Issue](https://github.com/your-org/animus/issues) for bugs
- Tag `@your-org` for architecture questions
