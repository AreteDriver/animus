# ADR-006: Public/Private Repository Split

**Status**: Accepted  
**Date**: 2026-06-29  
**Author**: AreteDriver  
**Class**: ARCH (Architecture)

## Context

The Animus monorepo (`github.com/AreteDriver/animus`) is currently private. This blocks:
- Free GitHub Pages documentation hosting
- External contributions
- Community trust and transparency
- Open-source tooling integration (e.g., FOSSA, Snyk free tier)

The repo contains a mix of public-safe content (code, tests, schemas, docs) and owner-private content (memory dumps, API keys, eval results with PII).

## Decision

Adopt a **two-repo model**:
1. **Public**: `AreteDriver/animus` — code, tests, docs, synthetic fixtures, infrastructure definitions
2. **Private**: `AreteDriver/animus-private` — owner data, secrets, PII, production configs

Prioritize **making the public repo public** as the default path. Use Cloudflare Pages or Netlify as a fallback only if the hygiene audit reveals secrets in git history that cannot be safely purged.

## Rationale

| Option | Public | Private Split | Notes |
|---|---|---|---|
| Single private repo | ❌ | N/A | Current state; blocks Pages and contributions |
| Single public repo | ✅ | N/A | Risky if any PII leaked in history |
| Two-repo (chosen) | ✅ | ✅ | Clean separation, history can be filtered |
| GitHub Pro | ✅ | N/A | $4/mo; keeps private but solves Pages only |

The two-repo model is the only option that simultaneously:
- Enables public contributions
- Provides free docs hosting
- Keeps owner data isolated
- Allows gradual migration rather than big-bang exposure

## Consequences

**Positive**:
- Free GitHub Pages deployment
- External PRs and issue reports
- Community trust through transparency
- Separation of concerns (code vs data)

**Negative**:
- Must maintain two repos
- Risk of accidentally committing private data to public repo
- History rewrite required if secrets found
- Contributors need access to public repo only (simpler onboarding)

**Mitigations**:
- `.gitignore` already blocks `user_data/`, `personal/`, `.env`, `secrets.yaml`
- CI job (`.github/workflows/security.yml`) runs gitleaks on PRs
- Pre-commit hook suggestion in `docs/contributing/setup.md`
- Quarterly key rotation policy

## Implementation

1. Complete hygiene audit (see `docs/operators/migration-guide.md`)
2. Purge secrets from history via `git-filter-repo` if needed
3. Make `animus` repo public
4. Create `animus-private` repo for owner data
5. Enable GitHub Pages on public repo
6. Archive old evidence bundles or migrate to private repo
