# ADR-003: Schema Compiler with datamodel-code-generator

**Status**: Accepted
**Date**: 2026-06-27
**Decision**: Use `datamodel-code-generator` to auto-produce Pydantic v2 models from JSON Schema contracts

## Context

`packages/contracts/` held 20 canonical JSON schemas defining actions, events, assessments, memories, and traces across all Animus subsystems. These schemas were **pure JSON** — no Python package could import them. `packages/types/` only had 3 security-related files (`sensitivity.py`, `egress.py`, `secrets.py`). Phase 1 of the roadmap required schemas to be importable as Python.

## Options Considered

| Option | Pros | Cons |
|---|---|---|
| A. datamodel-code-generator | Handles `$ref`, enums, `allOf`, `const`/`Literal`; proven tool; 1-command generation | External dependency; generates verbose code; needs post-processing |
| B. Manual Jinja2 templates | Full control; no external deps | Brittle; must manually track schema changes; high maintenance |
| C. `jsonschema` + runtime dicts | Zero generation step | No IDE support; no type checking; validation only, not modeling |

## Decision

Adopt **Option A** (`datamodel-code-generator`) with custom post-processing:

1. Generate to temp dir with `--use-union-operator --target-python-version 3.12`
2. Post-process: rename base class `AnimusCanonicalObjectEnvelope` → `Common`
3. Post-process: remove duplicate enums from individual modules (they live in `common.py`)
4. Post-process: fix imports `from .common_schema` → `from .common`
5. Commit generated code to `packages/types/src/animus_types/` so CI validates against it
6. Provide `scripts/compile_schemas.py` for re-generation

## Consequences

- 20 JSON schemas now importable as Pydantic models
- `packages/types/` grew from 3 files to 24 (21 generated + 3 legacy)
- Round-trip tests added (`packages/types/tests/test_schemas.py`, 22 tests)
- `packages/contracts/` gets `pyproject.toml` — now a real package
- Dependency on `datamodel-code-generator` for re-generation (not runtime)
- Generated code uses `constr`, `conint` (deprecated in Pydantic v3) — may need migration when v3 ships
