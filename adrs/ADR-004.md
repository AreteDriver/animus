# ADR-004: Truth Baseline Command Failure Detection

**Status**: Accepted
**Date**: 2026-06-27
**Decision**: Make `check_test_count` FAIL on non-zero exit codes regardless of `expected` value; add `version_alignment` check

## Context

`scripts/truth-baseline.py` ran 8 checks, two of which were silently broken:

```toml
[[checks]]
type = "test_count"
name = "core_tests"
command = "python -m pytest --collect-only -q"
```

When `python` was not found in the environment, the shell returned exit code 127. The checker parsed 0 tests, did not detect the command failure, and marked it PASS because `expected` was `None`.

This produced a **false positive** — a broken check reporting success. The roadmap claimed "Truth baseline: 8/8 passing" but two checks were meaningless.

## Decision

1. **Fix `check_test_count`**: If `rc != 0`, return FAIL immediately. Do not evaluate `expected`.
2. **Add `python3` fallback**: When `python` returns 127, retry with `python3`.
3. **Add `expected = 1`, `op = ">="`**: Verify at least one test exists.
4. **Add `version_alignment` check**: Read all `packages/*/pyproject.toml` and `pwa/package.json`, report mismatches. Document `contracts/` as exception (no manifest).

## Consequences

- Baseline now reports **6 PASS / 3 FAIL** — honest, not falsely optimistic
- Exposed real issues:
  - `core_tests` FAIL: ImportError in `conftest.py`
  - `forge_tests` FAIL: pytest returns rc=2 despite 9425 collected tests
  - `version_alignment` FAIL: 7 unique versions across 8 packages
- All future command-based checks must handle exit codes explicitly
