# ADR-002: Audience-Based Documentation Tree

**Status**: Accepted
**Date**: 2026-06-18
**Decision**: Reorganize `docs/` from flat graveyard to audience-based lanes

## Context

`docs/` was a flat directory of 44 markdown files with no index, 6+ broken internal links, stale test counts, and no navigation structure. New contributors could not find installation instructions, architecture docs, or package references. The existing content was accurate in pockets but buried under session notes and outdated whitepapers.

## Decision

Adopt an audience-based documentation tree with 7 lanes:

| Lane | Audience | Contents |
|---|---|---|
| `getting-started/` | New users | Quickstart, installation, concepts |
| `architecture/` | Contributors, architects | v2.1 planes, ADRs, standards |
| `packages/` | Package consumers | Per-package READMEs, version matrix |
| `contributing/` | Developers | Setup, workflow, debugging |
| `operators/` | Self-hosters | Deployment, config, monitoring |
| `reference/` | Everyone | Glossary, FAQ, changelog, security |
| `roadmap/` | Stakeholders | Milestones, blockers, next actions |

Additionally:
- Add `scripts/docs-validate.py` — CI gate for internal links, anchor references, trailing whitespace, redirect stubs
- Add MkDocs with Material theme for rendered site
- Update root `README.md` with new nav links

## Rejected Options

1. **Keep flat structure + add index.md** — Does not solve discoverability; index would become stale
2. **Move docs to wiki / external host** — Loses version control, harder to validate in CI
3. **One README per package only** — Does not address cross-cutting concerns (architecture, operators, contributing)

## Consequences

- All 179 markdown files now pass link validation
- MkDocs builds clean (0 warnings, 23MB site)
- Package READMEs written for Quorum, PWA, Contracts (previously missing)
- Architecture overview rewritten for v2.1 reality (8 planes)
- Maintenance burden: every new doc file must be added to `mkdocs.yml` nav
