# ADR-005: Kernel Extraction as Standalone Package

**Status**: Accepted
**Date**: 2026-03-15
**Decision**: Extract the autonomous builder engine from Forge into a standalone `packages/kernel/` package

## Context

`packages/forge/` grew to 352 source files and 276 tests. It contained both the multi-agent workflow orchestration layer (YAML pipelines, agent archetypes, quality gates) and the low-level autonomous builder engine (budget accounting, async DAG scheduling, sandbox validation, resume state). The monolithic structure made it hard to reason about Forge's surface area and prevented the builder engine from being used independently.

## Decision

Extract the following into `packages/kernel/`:

| Component | Files | Responsibility |
|---|---|---|
| Budget Manager | ~15 | Token accounting, spend tracking, cost ceiling enforcement |
| Executor | ~25 | Async DAG scheduling, step dispatch, checkpoint/resume |
| Sandbox | ~12 | Test-driven validation before applying changes |
| Safety Checks | ~8 | Config validation, guardrail enforcement, forbidden skill blocking |
| Resume | ~10 | State persistence to SQLite, workflow recovery on failure |

Total: 172 files, ~55K LOC extracted. Forge retains the orchestration layer (YAML parser, agent archetypes, evaluation framework, metrics).

## Consequences

- **Kernel** is now independently importable: `from animus_kernel import Sandbox, BudgetManager`
- **Forge** shrinks to ~180 files focused on orchestration and evaluation
- **Testing gap**: Kernel has only 8 tests for 189 files — coverage must be addressed before durable core integration
- **Version divergence**: Kernel is at 0.1.0 while Forge is at 1.9.0 — alignment needed
- **Import verification**: `scripts/verify_imports.py` confirms all critical imports resolve post-extraction
