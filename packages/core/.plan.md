# Plan: AI-Spend Session Guard Integration

## 1. Provider-Aware Pricing in session-guard.sh

**Problem:** `_compute_cost()` uses hardcoded Anthropic pricing (`input*0.000003 + output*0.000015`) regardless of actual model.

**Approach:**
- Add `_detect_dominant_model(file)` that scans the transcript for `model` fields and returns the most frequent model.
- Add `_get_model_pricing(model)` lookup table with known rates for:
  - `kimi-k2.6` (~$0.0005/1K input, ~$0.0015/1K output)
  - `claude-sonnet-4` / `claude-opus-4` (actual Anthropic rates)
  - `gpt-4o` (OpenAI rates)
  - `qwen2.5-coder` / `llama3` (Ollama local → $0)
- Modify `_compute_cost(file)` to detect model first, then use model-specific rates.
- Default to Anthropic rates if model is unknown.

**Files:** `ai-spend/scripts/session-guard.sh`

## 2. Ollama Provider for ai-spend

**Problem:** Ollama doesn't expose token usage via API. The `/api/ps` endpoint shows running models but no counters.

**Approach:**
- Add `OLLAMA = "ollama"` to `ProviderType` enum in `models.py`.
- Create `providers/ollama.py` that reads Claude Code transcripts for Ollama-backed sessions.
  - Scans `~/.claude/projects/*/*.jsonl` for `model` fields matching Ollama model names.
  - Extracts `usage.input_tokens` and `usage.output_tokens` from those transcripts.
  - Computes cost as $0 (local inference) but records token counts for visibility.
  - Alternatively, can use a lightweight log parser for `journalctl -u ollama` to count requests.
- Register in `providers/__init__.py`.
- Add to `providers/registry.py`.
- `validate_credentials()` checks `curl http://localhost:11434/api/tags`.

**Files:**
- `ai-spend/src/ai_spend/models.py`
- `ai-spend/src/ai_spend/providers/ollama.py` (new)
- `ai-spend/src/ai_spend/providers/__init__.py`
- `ai-spend/src/ai_spend/providers/registry.py` (already auto-imports)

## 3. Wire Session-Guard Markers into ai-spend SpendStore

**Problem:** Marathon markers are written as JSON files to `~/.local/share/ai-spend/marathons/` but never ingested into the SQLite database.

**Approach:**
- Add new CLI command: `ai-spend markers ingest`
  - Reads all `.json` files in `~/.local/share/ai-spend/marathons/`.
  - Parses each marker: `session_id`, `cwd`, `date`, `cost_usd`, `turns`, `drift_pct`, `alerts`.
  - Converts to `UsageRecord` with:
    - `provider_id = "claude-code"` (or detected provider from model)
    - `provider_type = ProviderType.MANUAL` (or a new `TRANSCRIPT` type)
    - `model = "unknown"` (or from marker)
    - `cost_usd = marker.cost_usd`
    - `input_tokens = 0` (not in marker yet)
    - `metadata = {"session_id": ..., "cwd": ..., "alerts": ...}`
  - Upserts into `SpendStore` via `add_usage_records()`.
- Update `session-guard.sh` marker format to include `model` and `provider_type` fields.
- Add `ai-spend markers list` to show ingested markers without re-ingesting.
- `ai-spend summary` will automatically include these because they're in `usage_records`.

**Files:**
- `ai-spend/src/ai_spend/cli.py` (new `markers_app` Typer subcommand)
- `ai-spend/scripts/session-guard.sh` (enhanced marker JSON)

## Open Questions

1. Should we add a new `ProviderType.TRANSCRIPT` or use `MANUAL` for marker ingestion?
2. Should Ollama cost be $0 or should we allow a custom `cost_per_million_tokens` config for local inference (electricity/depreciation estimate)?

**Recommendation:** Use `MANUAL` for markers (they're effectively manual entries derived from transcripts). For Ollama, allow a configurable `cost_per_million_tokens` defaulting to $0 but letting users set e.g. $0.50/1M to account for electricity.
