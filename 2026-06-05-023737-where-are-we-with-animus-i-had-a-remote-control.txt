  Good question, because the current /exit→edit→restart dance is genuinely
  painful — especially over phone-remote during a shift. Here's the reframe that
  opens up better options:

  The off-session dance is only required because secret values transit the 
  model's context. Two leak vectors (file-mod hook pipes diffs; Bash stdout
  lands in transcript). Kill the value-transit and the /exit requirement
  evaporates for the common case. And notice: what actually broke your backups 
  for days was 100% structural — lost KEY= prefixes, a placeholder bucket, a
  mashed path. Zero secret content. Under a better design that would've been a
  30-second in-session fix, not a parked off-session blocker.

  So the question is really: how do I make structural edits to 
  credential-adjacent config without secrets being in the file the model 
  touches?

  Three approaches, distinct tradeoffs

  1. Split structure ↔ secrets (cheap, highest 80/20).
  animus.env currently mixes non-secret structure (repos, paths, bucket names)
  with the 3 real secret lines (B2 key, password, account id). Split into:
  - animus.conf — repos/paths/buckets → model edits freely, in-session, no leak
  - animus.secrets.env — just the 3 key lines → rarely changes, stays
  off-session
  The thing that broke lives in the non-secret file. ~10 min to do, and I can do
  most of it in-session. This alone removes ~90% of your off-session edits.

  2. Secret-reference indirection (proper fix — eliminates the class).
  Store the actual secrets in a real manager and have the env hold references,
  not values:
  - pass (lightweight, gpg-backed, git-friendly) → RESTIC_PASSWORD_COMMAND="pass
  show animus/restic", B2 key via pass
  - or op (1Password CLI) → op://vault/restic/key
  - or sops+age (file-level encryption, decrypt at service runtime)
  The env file then contains no secret values at all → fully model-editable
  forever. Highest setup cost; needs you to pick a backend (do you already use
  1Password? is gpg set up?). This is the real long-term answer.

  3. Redacting hook on secret-pattern paths (upgrade the existing stack).
  You already run 19 hooks. Add one that, for paths matching
  *secrets*/*.env/*/restic/*, redacts secret-regex matches to <REDACTED> in both
  the Read content and the post-edit diff before they reach the model. Then the
  model can edit secret files in-session and simply never receives the values.
  Medium effort, reuses your infra, no external dependency. Risk: regex misses a
  novel secret shape — so it's a safety net, not a guarantee.

  Do #1 now, layer #3, treat #2 as the long-term. The split (#1) is cheap and
  directly addresses what actually bit you. The redaction hook (#3) covers the
